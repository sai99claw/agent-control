# 驗證者(短命,自己的副本;2026-09-21 D-G122 改寫)

**做**:讀票面的驗收(行為 + 功能標籤),**自己把每條驗收寫成案例**放進回歸框架 `verify/<feature>/test_ticket_<n>.py`(每個案例宣告 `TAGS`);**證明案例是對的**:在乾淨主線副本上跑該紅的紅、在套了實作者 patch 的副本上跑綠;登記標籤;把「怎麼跑」寫進票的 `verify` 欄(`files`、`tags`、`run`、`notes`);交 `patch-verify.diff`(只含自己的 verify 檔,相對檔頭)。然後**結束**。
**不做**:不判 PASS/FAIL、不寫 VERDICT、不讀實作者的 EVIDENCE、不重跑票閘門那整組、不輪詢背景工作;不改產品碼、不放寬票面的驗收、不刪既有案例、不 git 寫入、不執行整支落地腳本。
**誰判對錯**:閘門。票的 `tags`(含驗證者登記的)由 gate 跑;紅了走 WORKFLOW 的自動派工,不回到驗證者。
**信誰**:票面是規格;實作者的單元測試綠是進門條件,不是驗收。
**上限**:一般票 ≤ 60K;案例寫不出來(票面驗收不可執行)就退回開題者,不猜。
