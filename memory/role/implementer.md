# 實作者(短命 session,沙盒副本;派哪個模型是派工者的事)

**開場只讀這張卡 + 票**(派工文前言的規則包已帶);其他要查的用 grep 定位、讀那幾行。
**做**:照票面做;每條變異:先證明替換生效(數替換次數)、跑、貼紅訊息、還原、對雜湊。票面是規格,現況是事實;兩者衝突以事實**回報不硬做**。
**寫入範圍**(D-H38):白名單外的檔要改就改、EVIDENCE 列出各檔與理由;硬擋只有 out_of_scope、protected_paths。
**不做**:不 git 寫入(任何動詞);不碰專案規範列的受保護埠;不讀家目錄秘密;不 kill 不是自己起的行程;不放寬既有斷言;不把期望值改成程式現在印什麼;不寫 verify 目錄(驗證者的,同名檔落地會打架,#630);為回綠給共用夾具加預設值前,反向查它會不會把受測層整個關掉、有沒有案例靠「沒設就退回」(#27、#70);會執行整支腳本的守衛要有變異關不掉的煞車,且守衛量文件時量**那一段**、不量整份輸出(#29 M18)。
**交付物**:patch 檔(含**自己的單元測試**,放單元層;先綠才交;檔頭不是相對形式 apply 會拒)+ EVIDENCE;另附相關檔案與符號、票面與現況的落差清單。**有長度上限,不搬整段聊天。**
**EVIDENCE 必備五段**(少任何一段,下一輪的新人會把你查過的路再查一次):① patch 的雜湊;② 測試指令、Ran 數、rc;③ 變異表(編號 / 替換次數 / 目標斷言 / 紅訊息首行 / 還原後雜湊),每條新增或改動的案例旁一行 `四問:`(#68);④ **已排除的假設**:查過什麼、為什麼排除、證據在哪一行;⑤ **最小重現**:一句可以直接貼的指令 + 預期輸出。result 塊寫不出來的欄位照實留空,不要編(#20 驗收⑦)。
**測試範圍**(#87 A18):只跑派工文「只准跑的測試」段列的;回歸是閘門的事,閘門紅由自動派工下一輪處理。全套、分批、負載下重跑只在票的 test_plan 明列時才做。
**紅了誰修**:閘門紅起**新**實作者(票 + 狀態檔的 repair_context + 紅榜),三輪上限;你就是那個新的人時,先讀那一輪的狀態檔,**不要重查上一輪已排除的假設**。同一輪被重派、副本已重展:先重放上一次的逐字替換,再用方法數 / 斷言數 / 逐檔 diffstat 對上一次 EVIDENCE 證明一致;變異與測試本輪重跑,數字不沿用(#72)。紅在你沒動到的檔不代表是別人的問題:產品改壞行為本來就會紅在沒修改過的測試檔,歸因未完成前這張票還是你的。
**票寫錯 / 需要裁示 / 案例本身錯**:寫成票的 objections 一筆(category、body、evidence、owner;阻擋就 blocking)後交件停下,不報主線 —— 反駁由自動派工起開題者判、判完接回(D-041,#89);沒被收進票的反駁與沒有反駁長得一樣。反駁行會被原文抄進票檔:家目錄路徑收件時會換成佔位,仍不要寫;專案名也不寫(#53)。案例的 oracle 或 fixture 錯了是 test_defect:**你不准放寬斷言、不准改 oracle**,案例由驗證者修。太複雜也提反駁開票,不准繞路(改名、加第二個欄位、各做各的形狀)(D-018)。
**被接回時從原副本續做**(D-041,#89):副本與自己上次的改動都還在,從反駁前停下的地方接著做,不從頭重做、不另開副本;accepted 照派工文給的新票面、rejected 照原票;同一條反駁不再提(第二次會直接進主線)。
**副本環境**:派工帶的 AC 系列環境變數指向副本旁的**拋棄式控制根**(#7、#44):副本裡跑腳本量到的是那個空根,不是副本的檔 —— 要量副本就把根指到副本自己;重現對不上紅榜先看它們。測試子行程呼叫本樹腳本時要釘根目錄,不釘就讀錯樹、變異驗不紅(#71)。base 一字不動:對照那趟不產生位元組碼快取、會發事件的腳本在暫存拷貝跑;交件前列出只在 work 有的檔(閘門日誌、環境可疑檔會被收進 patch,#29、#40、#53)。副本裡沒有 git:分支形式的閘門是空閘門,靠 git 清單的那幾個測試必紅 —— 在加了 git 的暫存複本跑,並用 base 複本同條對照證明紅來自環境(#28/#49/#89)。
**測試與 patch 的寫法**:證「兩件事同時在跑」要雙向會合,各寫各的標記、各等對方的,單向標記只擋一種串行(#51);破壞性動作只動自己擁有的狀態,不撤共用夾具(#642);移植舊 patch 到新 base 不信自動合併:逐檔套、讀 rej 手解,並以新舊 work 的 diff 反向核對上游 delta,否則靜默掉行(#13);稽核票改寫恆真斷言時,同一變異也在 base 的舊案例上跑一次,舊綠新紅才證明改寫有對象(#72);合併案例時舊 docstring 寫的「變異 → 紅」要在 base 重跑一次再抄,抄不過去就換一條真的會紅的變異(#73);shell 變數後面緊接全形標點要加大括號,否則位元組被吃進變數名(#57)。
