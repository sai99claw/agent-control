**做**:照票面做;跑票閘門對照表挑到的那一組(副本裡沒有 `.git`,`--branch` 是空閘門,要用檔名形式叫);每條變異:先證明替換生效(count)、跑、貼紅訊息、還原、對雜湊。票面與現況對不上就**回報不硬做**。
**不做**:不 git 寫入(任何動詞);不碰專案 `CLAUDE.md` 列的受保護埠;不讀家目錄秘密;不 kill 不是自己起的行程;不放寬既有斷言;不把期望值改成程式現在印什麼;會執行整支腳本的守衛要有變異關不掉的煞車。
**交付物**:`patch.diff`(含**自己的單元測試**,放單元層;先綠才交;檔頭只准 `base/…` / `work/…` 的相對形式)+ `EVIDENCE.md`(patch sha256;閘門指令、`Ran N`、rc;變異表:編號/替換 count/目標斷言/紅訊息首行/還原後 sha256;票面與現況的落差清單)。
**信誰**:票面是規格,現況是事實;兩者衝突以事實回報。
**交付前的回歸(2026-09-21)**:票閘門的對照表對不到回歸層,所以綠不等於回歸綠。交付前必跑 `scripts/verify.py --tag <票的 tags 與動到功能的既有標籤>`、**整支瀏覽器模組**(不只對照表挑到的 class)、時序類的票再在負載下(`nice -n 19` + 4 支 `yes`,記 PID 只 kill 自己的)把新案例跑 **3 次**;三組 Ran/OK 貼進 EVIDENCE。一輪把同一層的 bug 全露出來。
**不准輪詢**:測試前景跑、給 timeout、只擷取 `^Ran |^OK|^FAILED|^(FAIL|ERROR):`;不用 Monitor / sleep 迴圈等背景工作 —— 每看一次就是整份上下文重送。
**紅了誰修**:閘門紅由落地器自動起**新**實作者(票 + 目前 patch + 紅榜 + 上一輪 EVIDENCE),三輪上限;你就是那個新的人時,票寫錯 / 需要裁示 / 紅在票沒動到的檔 → 停,報主線。
**交付後清副本**:交完就刪掉自己的 `work/` 與 `base/`,只留 patch 與 EVIDENCE。
