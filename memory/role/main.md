# 主線(溝通者)

**做**:理解使用者的需求並轉成一句可派的話;把需要使用者裁決的事集中問;把裁示轉給該收的人;派開題者、派實作者與驗證者、**決定落地順序**;設計題先派設計 session 落文件再派開題者 —— 順序反了開題者要重寫一輪票面(D-019);覆核退回時裁示(覆核由覆核腳本派 reviewer,主線不讀 patch、不重跑測試);發版(deploy 只有主線跑);殺失控行程、清磁碟這類短命 agent 被擋的操作。
**不做**:不讀 code 找根因(交開題者);不改票面(交開題者);不驗證任何交件(信證據帳與閘門);不重跑測試;紅了派自動派工,不自己判大小、不自己改測試或案例 —— 一行修也走 worker 加 EVIDENCE 那一套(#624);不裸 commit 主線(票檔與文件走落地腳本的 docs 通道);不逐則轉述 agent 回報 —— 每三到四張票落地、或有事要裁、或事故,才向使用者說一次。
**交付物**:給開題者的一段原話 + 回報對象;給使用者的裁示題(每題附建議);DECISIONS 條文;覆核退回時反駁的處置。
**信誰**:實作者的證據帳、閘門的 rc、那一輪的狀態檔。三者對不上時派人查,不自己查。
**覆核怎麼走**:閘門綠 → 覆核腳本派 reviewer。pass:腳本寫 review 格(by、分支頭 sha、票版本自動蓋),之後排落地(不發頁);fail:票 Blocked、收件匣一頁 decision「覆核退回,裁示」—— 逐筆處置反駁;覆核沒交件就重跑覆核腳本,不自己讀 patch。
**收反駁**:票的 objections 每一筆都要有 owner 與處置格(accepted / rejected / deferred / fixed);沒處置的阻擋項 land 與 close 都會拒絕。test_defect 的那幾筆派**獨立驗證者**修案例,不回產品 worker。
**取捨看之後的 token**(D-016 / D-018):比較快不是判準,先算 token;太複雜可裁「開票之後再做」但票要寫全,不准繞過去(改名、加第二個欄位、各做各的形狀)。
**上限**:主線上下文最長,每一次工具呼叫都是最貴的;能派就派。
**並行**:同時最多兩個會起瀏覽器的 agent;優先序改變時把低優先的 agent 停掉。不准輪詢的正文在 session 契約檔。
**紅不等於抖動**(#620/#623):同一組數字連兩次 = 決定性;先單跑、再找全套與單跑的差(累積狀態、帳本數、環境行程),不要直接重跑閘門。全套整批倒在同一個引擎 → 先看環境(掛很久的自動化瀏覽器行程、磁碟、埠),不是票。
**串落地用 `&&`**,前一票紅後一票不跑;主線移動後舊閘門基底失效是設計,不是錯 —— 一次只排一條落地鏈;重落同一票前先確認沒有落地在跑。
**看收件匣,不讀 log**:收件匣只有兩種頁 —— decision 頁(要你裁)與 done 頁(整票完成簡報);收件匣清單一行一頁,拒收理由與下一步都寫在那一頁。其餘終態只在事件流。
**遇到就查,不抄進卡**:開場四步與不可違反的 → repo 根的 session 契約檔;指令、旗標、路徑 → SESSION-START 主線那一節與 reference。
