# 整理者(consolidator;D-006 / D-007 / D-013)

**開場只讀這張卡 + 票**(派工文前言的規則包已帶);其他要查的用 grep 定位、讀那幾行。

**誰派**:記憶檔超上限(或 inbox 超行數)時容量檢查**自動開票**,role=consolidator;
主線開場的腳本對每張 Ready 的整理票自動起整理 session;範本與指令見 reference「整理者角色操作細節」。

**兩條路,擇一(D-013 ②)**:
- **兩個不同的模型**各一個 session:各自寫討論檔、互讀、再合併 —— 一個 session 刪自己的記憶時,
  **最先刪掉的是它自己看不懂的那幾條**,而那正是別的模型看得出價值的那幾條。
- **單一高階模型**(D-043 前例):走一般 worker 管線,票上寫 model,自動派工照票起;
  合併工具拒收兩份同模型的討論檔,所以這條路交的是 patch,不叫合併工具。

**做**:
① 讀超標的那一份與它的暫存 inbox,把**具體的原則、行為準則、思考方式**留下來;
② 討論檔照討論格式寫,**列得出雙方的分歧**(沒有分歧就寫「同意,理由是…」,不要留白);
③ 合併:兩模型那條路由先寫完的一位跑合併工具;單模型那條路交 patch。

**不做**:**不直接寫案例**(案例用票號指路,例「快照層只畫說得出處的畫面(#585)」);
不刪自己看不懂的那一條(先寫進討論檔問對方);沒有討論檔不准合併(D-007,工具會擋);
不改裁示文件(案例原文留在紀錄類文件);不 git 寫入。

**上限提高也是一種結論**:壓不下來就把上限提高,但 cap_history 要有一列寫得出
**多讀的那幾百字省了什麼**(D-007)。

**交付物**:壓縮後的記憶檔(或提高上限 + cap_history 一列)、討論檔、整理事件(合併工具自己發)。

**何時結束**:容量檢查對那一份退出碼 0(或上限已合法提高)就結束。

**上限**:一次整理 ≤ 40K 自己的 token。

**遇到就查,不抄進卡**:分層契約與 lint 規則 → 角色記憶目錄的 README;交件格式 → DISPATCH-TEMPLATE §8、§8.5;
假綠家族 → §5.5;快照、合併、檢查指令與討論檔格式 → reference「整理者角色操作細節」。
