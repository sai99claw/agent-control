# 派工範本 —— 給實作 agent 的指令長什麼樣

**這份文件的出處**:2026-09-10 一個長命的調度 session 一天之內派了八張票、落地十一張
(那個角色 2026-09-21 已退場,D-010;踩出來的坑留著),
下面每一條都是那天**實測出來或踩出來**的,不是從別處抄的慣例。標 🩸 的是踩過的坑,
標 📏 的是當天實測(`ls` / 真的跑一次)確認的事實。實例都來自前一個專案
(2026-09-08 → 09-12),日期逐條寫在原處。

**為什麼理由要跟規矩寫在一起**:一條沒有理由的規矩,三個月後會被人當雜訊繞過去 ——
而繞過去的那個人不會知道它擋的是什麼。

**這一份是通用版。** 專案特有的東西(埠、目錄、測試陷阱、哪一支腳本不准在副本裡跑)
寫在專案自己的 `CLAUDE.md`(範本:`templates/project-CLAUDE.md`),派工時兩份一起給。

## 派工時**不要整份貼這一份**(2026-09-21,D-015)

```sh
python3 scripts/rules.py pack worker --model opus      # ≤ 4 KB 的派工文前言
python3 scripts/rules.py roles                         # 哪個角色要哪幾節
```
`rules.py pack` 從這一份抽**那個角色真的會被擋到的幾節**,接上角色卡與那個模型自己的記憶,
壓進 4 KB,並在砍掉的地方指名「全文見哪一份的哪一節」。理由是 token 帳:整份是一萬多個字,
而一個實作者會被擋到的是其中幾節、驗證者是另外幾節 —— **每派一次工,每個 agent 各付一次整份的錢**。

節錄不是全文:被派的 agent 開場自己讀 `memory/role/<角色>.md` 與這一份,前言只負責指路與
留住會被擋到的那幾句。

## 0. 派工路由:哪一種工作找誰

表在 `docs/ROLES.md` §模型路由,可調的那一份在 `board/config.json` 的 `routing`。
**不要把這張表抄進派工文** —— 抄過去的那一份會過期,而過期的那一份跟現在的長得一樣。

額度用完時的政策也在那裡:**等、換、或送進收件匣;不准默默改走付費通道。**

## 0.5 路徑:先確認,不要照著印象寫

📏 派工文裡每一條 `cd`、每一個 `--prefix`,**寫之前 `ls` 一次**。

🩸 2026-09-10:派工文寫成「在 `work/<子目錄>` 底下跑 `npm ci --prefix tools/compat`」,
而 `tools/` 在 **repo 根**。這一條錯過兩張票沒有人吭聲,正是因為那個子目錄底下**真的
也有一個叫 `tools/` 的東西** —— 「tools 在底下」看起來成立。第一張票的 agent 自己摸對
了位置沒說,第二張撞到 `EUSAGE: can only install with an existing package-lock.json`
才報上來。

## 1. 副本 + patch:實作 agent 不碰 git

給它兩個目錄:`$W/work`(改這個)與 `$W/base`(**一個字都不准動**,它是 diff 的對照
組)。兩個都用 `git archive <ref> | tar -x -C …` 展開,所以裡面沒有 `.git`,它想寫也
寫不了。交付:

```sh
diff -ruN -x node_modules -x __pycache__ -x '*.pyc' base work > patch.diff
```

**禁止一切 git 寫入動詞**(`add` / `commit` / `checkout` / `branch` / `worktree` /
`push` / `stash` / `reset` / `merge` / `rebase` / `tag` / `clean`)。

**為什麼**:落地要決定分支順序、要在 land 佇列裡排、要處理與別張票的衝突,而實作
agent 看不到別張票。它自己 commit 出來的東西,落地那一側還是得拆開重放一次。

🩸 **`git archive <ref>` 之前先唸一句 `git log --oneline -1 <ref>`,對一眼那個標題是不
是你以為的那一張。** 2026-09-10:有人漏了 `git commit` 就拿那條 branch 去做下一張票的
base 副本,得到一份**看起來完全正常、其實少了一張票**的樹 —— `git archive` 給的是
commit 的內容,worktree 裡沒 commit 的東西一個字都不會進去,而**它一聲都不吭**(同一個
漏掉的 commit,`land.sh` 那一側至少還印了個 `0`)。

這是一個**固定動作,不是一支工具**:要擋的是「忘了看」,而工具擋不住沒人叫它。印出來
的那個 sha 就是派工文裡「base = main `<sha>`」要寫的那一個,也是票上 `base_sha` 那一格
(`tickets/SCHEMA.md`),三處出自同一次 `git log`。

📏 套 patch 的人要看 `patch.diff` 第一行 `---` 的路徑決定 `-p` 幾:前綴是
`base/<子目錄>/…` 就是 `-p1`。**用錯會刪檔**。套完檢查
`find . -name "*.rej" -o -name "*.orig"`。

## 2. 禁區

- **埠**:`<受保護的埠>`(prod / staging / 看板 / portal)。自己起的測試 server 用 OS
  自動配的埠(`("127.0.0.1", 0)`)。
- **目錄**:`<資料與秘密目錄>`。
- **指令**:`<副本裡不准跑的腳本>`(部署、建置、發版、容器、服務管理)。發版是主線的事。

這三格由專案填(`templates/project-CLAUDE.md`)。**空著的派工文不要發** —— 一份沒有
禁區的派工文,跟一份禁區剛好是空的派工文長得一樣。

🩸 **不准殺任何不是自己起的行程**;不准 `pkill -f`、不准 `killall`、不准照著 `ps`
的輸出猜「這看起來像我的」。2026-09-10 有 agent 在等測試時用 PID 殺行程,殺掉的是
**另一條線正在跑的回歸測試**。這台機器上同時有好幾條線在跑,殺錯一發就是別人幾十
分鐘的工作。測試卡住就用 `timeout` 包起來重跑,不要去獵行程。

## 3. 判綠只能看測試自己說的話

🩸 **`cmd | tail`、`cmd | grep`、`cmd | head` 的退出碼都是右邊那一支的。**
實測:`sh -c 'false | tail -1'` 退出碼是 **0**。

所以「跑完 `| tail -6` 看一眼」在三種情況會靜靜判成綠,而三種都發生過:

1. 測試根本沒跑起來(import 就炸、副本沒裝依賴、指令打錯);
2. `Ran … / OK / FAILED` 那幾行**不在** `tail -N` 的視窗裡 —— 瀏覽器那幾支會在摘要
   後面再印一大段,2026-09-10 就是這樣把一支沒驗過的分支排進 land 佇列;
3. 管線中途斷掉(`head` 提早關掉、`SIGPIPE`)。

**正確形狀**:

```sh
sh scripts/gate.sh --branch --base > gate.log 2>&1; rc=$?
grep -aE "^Ran |^OK|^FAILED" gate.log      # 給人看的
[ "$rc" -eq 0 ] || { echo "紅了,看 gate.log"; exit 1; }
```

背景跑的一樣中招。

## 4. 不准收窄執行環境(瀏覽器引擎、平台、資料庫版本)

**不要設「只跑某一個引擎」那種環境變數。** 不設它拿到的就是這台機器此刻真的驅動得動
的每一個;測試框架的 `available()` 會把跑不動的標成「量不了」**並印出原因**。

🩸 2026-09-10:一支「只記不改」的 `fetch` 包裝寫成
`const real = window.fetch; real.apply(this, a)` —— Firefox 對 `fetch` 的 `this` 是
認真的,拋「'fetch' called on an object that does not implement interface Window」;
Chrome 完全不管。分支閘門收窄成 chrome 全綠,一路藏到 land 的全套才爆,白跑九分鐘。
(修法:`window.fetch.bind(window)`。)

只有**完全不碰那一側**的票才可以為了速度收窄。

## 5. 變異驗紅:沒驗紅的測試等於沒有測試

每一條寫成「改什麼 → 哪條斷言紅 → 失敗訊息片段」,做完還原(還原後對 sha256)。

🩸 **變異之後,先確認被改的那一行真的變了,再看測試紅不紅。** diff 一下、或把那一行
印出來。2026-09-10 有個 agent 第一次做變異時 `str.replace` 打到錯的位置,等於沒有
變異,而測試是綠的 —— 它差一點就把「守衛沒抓到」寫進回報。**「變異沒生效」與「守衛有
漏洞」長得一模一樣**,而那正是這一整類假綠的母題。那位 agent 自己發現並在回報裡寫明
「那是我的腳本錯,不是守衛漏」—— **這一筆比它修的 bug 更值錢**,照這樣誠實記下來。

**不准為了讓測試綠而放寬既有斷言**(把逐字比對改成 `assertIn` 之類)。真的需要放寬,
單獨提出來讓人裁。

🩸 三個 2026-09-10 實測「變異沒殺掉,而測試看起來是對的」的例子,值得當範例讀:

- **`overflow: hidden` 的容器照樣寫得進 `scrollTop`**(CSSOM 允許程式捲一個使用者
  捲不動的盒子)。所以「捲到底驗尾端可達」對一個被裁掉的頁面是綠的。改成直接量
  `getComputedStyle(el).overflowY` 才紅。
- **判準選到「壞掉時碰巧為真」的那一個**:用「某個訊息區上有字了沒」證明某件事,而那
  句話**壞掉的時候會先成立**。判準要選壞掉時**必然為假**的那一個。
- **`guard()` 的鎖吃掉證據**(某個 per-button inflight 鎖讓壞掉的版本與正確版本送出
  的請求數逐字相同)。

## 5.5 🩸 常設條款:「沒有東西可做」與「做完了」長得一樣

> **`[]` 是「看著,而一發都沒有」,`None` 是「這台根本沒在看」。**

那兩件事揉成同一個空 list 的那一刻,「一發請求都沒有」那種斷言就永遠是綠的,而且
**與真的驗過長得一模一樣**。整節講的都是這一句話的各種穿法。

**這是假綠的母題,而且它會持續生產** —— 底下的實例是 2026-09-10 一天之內遇到的
(來自前一個專案),其中**三個是當天新做的東西自己帶來的**,不是遠古遺留。所以這一節
是常設條款,不是歷史紀錄。

| 現象 | 為什麼看起來是綠的 | 抓到它的是什麼 |
|---|---|---|
| `cmd \| tail -6` 判綠 | 管線的退出碼是右邊那支的,`false \| tail` 退出碼 0 | 寫檔後 `rc=$?`,再讀 `Ran … / OK / FAILED`(§3) |
| `var(--fg)` 指著契約裡不存在的 token | `var()` 語法合法,整條 `color:` 在 computed-value time 才無效,瀏覽器靜靜退回繼承色 | 反方向守衛:每個 `var(--…)` 都要在契約裡 |
| `posted()` 在非 Chrome 引擎回 `[]` | `getattr(browser, "_pending", [])` —— WebDriver 沒有那一格,「答不出來」被寫成「答案是沒有」 | 讓它拒答而不是回空 |
| 變異沒生效 | `str.replace` 打到錯位置,檔案沒變,測試當然綠 —— 而那讀起來像「守衛沒抓到」 | 變異後先 diff / 印出那一行,確認真的變了 |
| `if __name__` 擺在檔案中間 | 直接跑時後面 34 條還沒定義就開跑,`Ran 112 tests / OK`;`-m unittest` 是 146 | 兩種跑法的測試數要相同 |
| `land.sh` 收到 0 個 commit | 照樣跑完整套九分鐘,綠了還說「main -> <原本的 sha> 已推上」 | 開跑前印出要落地的 commit 標題;0 就拒絕 |
| 那兩處字色從來沒生效過 | **畫面看起來一直很正常** —— 沒有人看得出來的壞,跟沒有壞長得一樣 | 反方向守衛;而發現它的是**換色時順手量對比**,不是有人覺得畫面怪 |
| 外部模型交回來的文案,提到一個**不存在的產品功能** | 它的表讀起來完整而具體,而**錯的那一格跟對的三格長得一模一樣** —— 沒有一個字看起來像猜的 | 凡是提到產品功能的字,對著 repo `grep` 一次(2026-09-10:外部模型給的文案寫「超出設定預算」,而那個 app 根本沒有預算功能) |
| 新的 `land.sh` 在演練裡十條全綠 | 那一輪落地跑的還是**舊的**(它從主線的工作樹執行)—— **在受控環境裡成立,與在真的路徑上成立,長得一樣** | 下一輪真跑時明確盯著新行為出現 |
| 關票前的字串檢查挑了一個原始碼裡根本不長那樣的字串(查 `hp-capital`,而那十二節是由清單產出的、字面只有一處) | `grep -c` 回 0,**跟「東西根本沒進主線」的 0 一模一樣**——驗證工具自己的輸入錯了,結果與被驗的東西錯了無法分辨 | 驗之前先看一眼那個字串在原始碼裡到底長什麼樣;挑「只有這張票才有、而且真的以字面存在」的字串(來自前一個專案,2026-09-12) |

### 過期的綠與有效的綠也長得一樣

同一個家族的另一面,而它咬的是**流程**不是程式:**「閘門綠」是對某一個 base 說的。**
分支擱著沒落地的期間主線會往前走,那個綠就從「這份改動是好的」變成「這份改動在
2026-09-10 中午對著那時的主線是好的」—— 而畫面上那一行 `OK` 一個字都沒變。

2026-09-10 實例:一張票因為 UI 方向未定被凍結,它的閘門(3470 條綠)跑在某個 commit;
凍結期間主線往前走了好幾步,中間進了主題色、對比表、以及**那張票動到的同幾支測試**的
多次改動。

**固定動作**:
- 記下每次閘門**跑在哪個 commit** 上(`git -C <worktree> merge-base main HEAD`),
  跟結果寫在一起 —— 那就是票上的 `base_sha`;
- **落地或解凍之前先比對主線現在在哪**,不同就重跑閘門,不要拿舊的那一行 `OK` 送。
  (`scripts/land.sh` 現在會替你問這一句:`base_sha` 不是主線祖先就拒絕。)

**判準,寫任何一個檢查之前先問**:

> **它答不出來的時候,長什麼樣?**

如果答案是「**跟通過一樣**」,那個檢查還沒寫完。

三個常見的「答不出來」偽裝成「通過」的形狀,看到就要停下來:
- **拿不到就當空的**:`getattr(x, "attr", [])`、`.get(k, "")`、`or []` —— 空集合對「有沒有東西」的斷言是通過。
- **能力不足被當成答案**:某個引擎 / 某個環境模擬不了,而程式回的是預設值而不是「我不知道」。
  正確做法是**明列並印出原因**,照抄那個形狀。
- **沒有輸入也算跑過**:0 個 commit、0 條測試、0 個檔案 —— 迴圈跑了零次是成功的。
- **在受控環境裡成立**:演練、沙盒、`--dry-run` 都是為了把代價拿掉,而拿掉的東西有時
  正好包含「這條路真的會被走到嗎」。十條測試全綠,而那一輪落地跑的還是舊腳本 ——
  **新行為第一次真跑是在下一輪**,那一輪才驗得到。發完新工具的人要自己排一次真跑的確認
  (`docs/REHEARSAL.md`)。
- **沒有人看得出來的壞**:兩處 `color:` 從來沒生效過,而畫面一直看起來很正常。抓到它的
  不是「有人覺得怪」,是**換色時順手量了對比**。所以「沒有人回報」不是證據 ——
  使用者回報得了的是**他知道該長什麼樣**的東西。
- **外部模型的具體與正確長得一樣**:向不在這個 repo 裡的腦袋要文案或方案,交回來的東西
  **具體程度是均勻的** —— 它不會在猜的那一格寫得比較模糊。所以**凡是提到產品功能、
  欄位、畫面元素的,一律對著 repo 查一次**再用。

## 5.55 🩸 常設條款:新工具的第一次真跑,要有人在場確認

演練綠只證明「在受控環境裡這樣寫是對的」。**新行為第一次真的被觸發的那一刻,才是它第一次
在真的路徑上成立** —— 而那兩件事在畫面上長得一樣(§5.5)。

**規矩**:發出一個新的守衛或工具的人,要**排一次真跑的確認**,並明確寫下**要看到什麼**。
不必為每一個各排一輪,但**下一次它第一次真的被觸發時,誰在場誰就確認一眼**。

那張清單住在 `docs/REHEARSAL.md`,控制台第 ⑤ 段會把它畫出來。**它不是待辦**,是
「哪些保證還只在演練裡成立」的清單。確認過的就把那一列刪掉。

## 5.6 🩸 演練環境要真,不要造一個自己寫的模擬器

> **「假一支出來,等於在測我自己寫的模擬器。」**
> —— 2026-09-10,一位實作者拒絕替 `land.sh` 造一個假的 git

派工文當時說「那個檔裡有現成的假 git 環境,照旁邊的做」。**那句話是錯的**(假 git 在
另一個檔),而它沒有照抄,理由比那個錯更重要:`land.sh` **通篇都是 git 語意**
(`merge-base` / `--no-ff` / `--ff-only` / `rev-list --count`),假一支出來,測到的是
那份模擬器對 git 的理解,不是 git。它改用 **tempdir 裡的拋棄式真 repo**。

**判準**:替演練造替身之前,先問 —— **這一段程式碼的正確性,是不是就寄託在被我替換掉的那
個東西的語意上?** 是的話就不能替換,要用真的。

**該替換的是「代價」而不是「語意」**:同一次演練裡它把全套閘門換掉了,換成一支
**寫一個標記檔就退出**的腳本 —— 那不但省掉九分鐘,而且讓「**全套到底有沒有被叫到**」變成
一個看得見的事實,而那正是那張票要問的東西(0 個 commit 卻照樣跑全套)。

| 換掉 | 為什麼可以 |
|---|---|
| 全套閘門 → 寫標記檔就退出 | 換的是**代價**;而且把「有沒有被呼叫」變成可觀察 |
| git 本身 → 假的 git | **不可以**,換的是**語意**,測到的會是模擬器 |

## 5.7 🩸 守衛的產出是一個**可執行的動作**,不是一句「有問題」

> **一個守衛給錯了下一步,跟沒有守衛不一樣 —— 它更糟。**
> 因為那個人會照著做,然後以為處理完了。

2026-09-10 的憑證守衛是範例。票面原本說「兩半:工作樹 + 索引」,實作時發現
`git ls-files --cached` **同時裝著「剛 `git add` 的」與「三個月前就 commit 了的」**,而對
後者說「現在 `git rm --cached` 還救得回來」**是一句假話**。所以它問三次,**每一格給不同的
下一步**:

| 格 | 怎麼問 | 訊息說的下一步 |
|---|---|---|
| 工作樹 | `git ls-files -z --others --exclude-standard` | 下一個 `git add -A` 會把它掃進去 |
| 索引 | `--cached` **且不在 HEAD** | `git rm --cached` **現在**還救得回來 |
| 歷史 | 在 `git ls-tree -r -z HEAD` 裡 | **清不掉,停下來報上去,不要自己刪** |

**變異驗紅要驗到「下一步是對的」**,不只是「有紅」:拿掉 HEAD 那一問,守衛照樣紅,但它
的訊息變成假話 —— 而那個變異如果只斷言「rc != 0」,它是綠的。

### 抓與放的代價不對稱:內容只用來**脫罪**,不用來**抓**

- **掃內容抓人會教會人繞過去**(把 key 拆成兩段字串接起來),而繞過去的那一份**看起來跟
  乾淨的一模一樣** —— §5.5 的母題。檔名這條線繞不過去:一份 token 存成檔案,那個檔就得
  有個名字。
- **抓錯了是吵一次**(有人看一眼就結案),**放過了是靜的**。所以脫罪那一段故意寫得笨,
  寧可多紅一次,也不加聰明的猜測。

**而且不加白名單。** 誤判的處置是**改檔名**,不是在守衛裡加一格例外 —— 加白名單只是把
這次的判斷藏起來,而它靜默失效的那天沒有人會知道。

### `-z` 不是效能參數,是正確性參數

`git ls-files` / `ls-tree` 不加 `-z`,非 ASCII 路徑會被**逃逸**印出來,而逃逸過的字串
`open()` 開不起來 —— **那會安靜地變成「掃不到」**。任何「列出檔案再逐一開啟」的程式碼都
吃這一條。

### 失敗訊息不要把秘密抄進第二個地方

守衛的訊息會落進 `gate.log`、CI 輸出、以及貼進對話裡的回報。所以訊息只說**第幾行、多長、
哪一種形狀**,不印那串秘密本身。

## 6. 查證

### 6.3 🩸 要數某條規則會抓到多少東西,就用**那條規則本身**去數

近似的搜尋條件數出來的是**假的下界**,而它看起來是一個**精確的數字**,不是一個估計 ——
那正是它危險的地方:讀的人不會知道要打折。

🩸 2026-09-10 一天之內三次,**每一次都是低估,而且每一次都寫成了確數**:

| 票面寫的 | 實際 | 為什麼差 |
|---|---|---|
| 「後面還定義了 **7 個以上**的 class」 | 漏掉 **34 條**測試 | 用眼睛數 class,沒有數測試 |
| 「分岔**不只一處、也不只一輪**」 | **246 處** + 123 格 | 抽樣看了幾支,沒有全掃 |
| 「**三處**寫死絕對路徑」 | **七處** | 用一個比守衛窄的關鍵字數的 —— **搜尋條件比判準窄** |

**規矩**:
- **要數某條規則會抓到多少,就用那條規則本身去數** —— 先把判準寫出來(哪怕只是一行
  `grep -E`),再用它數。不要用「我以為等價」的近似。
- **做不到的時候,把數字寫成下界並說明條件**:「**至少 N**(用 X 條件數的,與守衛的判準
  不同)」。一個標了條件的下界是有用的;一個沒標條件的確數是誤導。

**為什麼這件事會反覆發生**:寫票的人是在**還沒有守衛**的時候盤點的,所以他手上只有近似;
而實作者是在**裝上守衛之後**才看到真實範圍。**兩邊的數字不一致是常態,不是誰出錯** ——
票面把它標成下界,實作者就不必猜「是我看錯還是票寫錯」。

### 6.4 🩸 回報裡要標記:這是**讀出來的**還是**實測的**

**「讀 code 得出的結論」與「實測得出的結論」在回報裡長得一樣** —— 兩者都是一句肯定句,
兩者都可能對。差別在**它錯的時候誰會發現**:實測錯了,重跑一次就露餡;讀錯了,它會被
下游當成事實用下去,**而下游沒有辦法分辨**。

**規矩**:凡是寫進回報或票面的事實性斷言,**標記來源**。最省事的形狀是一句話 ——
「(讀 code 推的,未實測)」或「(實測:指令 X,輸出 Y)」。

🩸 2026-09-10 一天之內兩次:
- 有人**讀 CSS** 推斷某個焦點框對比不足,並據此要 agent 接受一個視覺改變 ——
  **實測是 5.70**(遠高於門檻),整段理由是錯的,而它讀起來跟量過的一樣篤定;
- 一張票面寫「實測 12.2 秒後」—— 真的去量是 **4.01 / 49.00 / 4.02 秒**,對不上任何
  一條路,而那個數字被寫在票上當作前提,一路傳到派工文。

**推翻上游指示的時候這條特別重要**:推翻需要的證據等級比照做高,而**「我讀了 code」
不是那個等級**。

## 6.5 發現問題與處置問題要分開

**掃到一個沒人料到的東西時,回報它,不要順手處理它。**

派工文裡的固定句(照抄):
> 如果你掃到 repo 裡**現在就有**長得像憑證的檔,**先停下來講**,不要自己刪。

為什麼這是一條規矩而不是客套:
- **處置需要的上下文,發現者多半沒有。** 那個檔可能是別人正在用的、可能是刻意留的、
  可能刪掉會讓另一條線的測試紅 —— 而掃到它的 agent 只看得到自己那份副本。
- **處置會把證據蓋掉。** 刪掉之後,下一個人看到的是「乾淨的 repo」,而不是「這裡曾經
  有一個差點被 commit 的憑證」—— 那正是這個守衛要記下來的事。
- **發現本身就是交付。** 一份「我掃到這三個,沒動」的清單,比一份「我清乾淨了」有用,
  因為前者可以被覆核,後者只能被相信。

同一條也適用於:掃到第三份重複的程式碼、掃到別的呼叫端犯同一個錯、掃到與票面無關的
既有 bug。2026-09-10 三次都是「列出未動」,**三次都是對的處置。**

## 7. 「票寫錯就說出來」

派工文最後一段固定要求:**發現票或驗收計畫哪裡與現在的程式對不上、或哪一條要求做不到
/ 做了會壞別的東西,直接說出來,不要硬做。**

📏 這一條當天回收率很高:一張票查出「圖示本來就是對的,問題在別的表面」因而沒有動任何
產品碼;一張查出票面那句「畫面上一個字都沒有」是照一行**讀了不存在節點**的失敗訊息
寫的;一張指出驗收計畫的用詞錯了。三次都是實作者對。

## 8. 回報格式(派工文要明列)

1. `patch.diff` 絕對路徑 + diffstat。
2. 做了什麼 —— **寫給不看 code 的人也讀得懂**(那份摘要會被轉給使用者)。
3. 測試輸出**逐字**(含 `rc=` 與 `Ran … / OK`),skip 的原因**逐字**貼上來。
4. 變異驗紅表。
5. **已排除的假設**:查過什麼、為什麼排除、證據在哪一行(2026-09-21)。
6. **最小重現**:一句可以直接貼的指令 + 預期輸出(2026-09-21)。
   5 與 6 是給**下一輪那個新的人**的:少了它們,三輪可能把同一段 code 查三次
   —— 而每一次都是整份上下文重付一遍。**有長度上限,不搬整段聊天。**
7. 票寫錯、發現的別的問題、**案例本身錯**(oracle 或 fixture):寫成票的 `objections[]`
   一筆(`category` / `body` / `evidence` / `owner`;阻擋就 `blocking: true`),
   不要只寫在回報裡 —— **沒被收進票的反駁,與沒有反駁長得一樣**。
   案例錯是 `category: test_defect`:**你不准放寬斷言、不准改 oracle**,主線會派獨立的
   驗證者修案例。

改到使用者看得到的文字時,**把「舊 → 新」的完整對照表列出來** —— 那是使用者會逐句看
的東西,不要只寫「已全部改為 X」。

## 9. 專案特有的那幾節

**這一份不收專案特有的東西。** 埠、目錄、不准跑的腳本、這個 code base 的測試陷阱
(那種「壞掉的版本與正確版本送出去的請求數逐字相同」的坑),寫在
`templates/project-CLAUDE.md` 複製出來的那一份專案 `CLAUDE.md` 裡,派工時兩份一起給。

理由:那幾節是**會過期的**,而這一份是**不會過期的**。混在一起的那一刻,兩邊會一起
被當成「上次那個專案的東西」跳過。
